# Writing Rules（表示規約）

Text Bank（Bundle文・Styleの6段階（L1〜L6）の文・Tendencyの6段階（L1〜L6）の文。2026-10-06に3段階（High/Mid/Low）から変更）およびResultDocumentを最終的な文章へ整える際の表示規約。ドメイン（値を決める）とプレゼンテーション（どう見せるか）の分離（[00-overview.md](00-overview.md)）における、プレゼンテーション側の文書である。

Composerはこの規約を適用しない（Composerは文言バンクからIDで選ぶだけ。[06-composer.md](06-composer.md)）。この規約が適用されるのは、①Text Bankの文言を執筆する時点、②ResultDocumentを最終出力へ整形する時点、の2箇所である。

## 規約

1. **高・中・低のいずれも肯定的に表現する**。Lowを欠点として書かない（例：行動主導性Low＝「受け身で消極的」ではなく「じっくり相手を見てから動く」。自立性Low＝「依存的」ではなく「相手と過ごす時間を何より大切にする」）
2. **能力ではなく傾向として記述する**
3. **性格を断定しない**
4. **優劣を示す表現を避ける**。High/Mid/Lowは母集団上の位置であり、良し悪しではない（[08-normalizer.md](08-normalizer.md)）。スコアの高低・総得点の比較を「強い/弱い」として表現しない
5. **相手（診断結果の読み手）を否定する語を使わない**
6. **Primitiveの名称は常に一行説明とセットで表示する**（例：「情動性──感情を深く受け取り、自分の想いも強く動く力」）。特に「情動性」は日常語彙として馴染みが薄く、単語だけでは意味が伝わらないため
7. **Tendencyは「〜の傾向があります」を基本形とする**。Tendency（結婚志向・浮気耐性）は性格だけでは決定できない概念であり（[05-tendency.md](05-tendency.md)）、価値観・経験・年齢の影響を受けるため、Styleより一段強く断定を避ける

## 6段階の文言への適用（2026-10-06）

結果画面のStyle/Tendencyの文言は6段階（L1〜L6。[08-normalizer.md](08-normalizer.md)「6段階」）で持つ（`inc/love-style-texts.php`・`inc/love-tendency-texts.php`）。**規約1〜7は6段階すべての文言に適用する**。規約1・4の「高・中・低」「High/Mid/Low」は、6段階ではL1〜L6のすべてを指す。

- L1・L6（両端）は傾向がいちばん表れやすい側、L2・L5（その内側）は同じ向きの傾向を、より穏やかな言葉で書く。どちらも規約3（断定しない）に従う。「L6の方がより〇〇が強い」「L2はL1より少し弱い」のように強さ・量の差として書かない。段階は母集団の中での位置であり、どの段階も優劣ではない（規約2・4）
- 段階名（L1〜L6・High/Mid/Low）は結果画面に出さない（下記「表示名の規約」1）
- Tendencyの文言の規約7への適合は次のとおり（2026-10-06に`inc/love-tendency-texts.php`の12本を機械で確認）
  - 第1文「〜傾向があります」は、6段階すべてが従う
  - 第2文「〜ようです／〜そうです」は、L2〜L5（L3は3段階のときのMidの文）が従う
  - 例外は結婚志向L1（第2文「自由な間柄だからこそ深まる愛情もあります。」）と浮気耐性L6（第2文「その誠実さが、揺るがない信頼につながります。」）の2本。3段階のときに承認された文（結婚志向Low・浮気耐性High）をそのまま使っているため

## 表示名の規約（結果画面のStyle/Tendency項目）

1. **正式な項目名（積極性・独占欲など）・段階名（High/Mid/Low）・点数は結果画面に出さない**（ユーザー決定 2026-10-06）。各項目は表示名・一行説明・文章だけで示す
2. **表示名は中立的な「話題の名前」にする**。どの段階の文章の見出しとしても合うようにし、特定の段階や良し悪しを連想させる語を使わない（例：「独占欲」ではなく「二人の距離感」、「浮気耐性」ではなく「ときめきとの付き合い方」）
3. **表示名と一行説明の定義は`inc/love-display-labels.php`（`LOVE_ITEM_LABELS`）に置く**。キーはStyle・Tendencyの項目名と同じにする。Composerは表示名を持たず、引数として受け取るだけである（[06-composer.md](06-composer.md)）

## 最終整形の責務

接続詞・文体・冗長さ・改行の調整は、Composerの出力（ResultDocument）を受けた後の整形工程が担う。この整形は文言の意味を変えない範囲に限る（意味を変えたい場合はText Bankの文言自体を修正する）。
